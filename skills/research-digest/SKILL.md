# Research Digest · 调研资料深度整理

目标：不是罗列链接，而是产出**可以直接据以行动**的结构化调研文档——读者看完知道读什么、按什么顺序、读到什么程度算够、以及这些材料与他已有认知的关系。

## 第零步：先明确四个上下文问题（不确定就问，或从对话推断并声明假设）

1. **目的**：学习入门 / 面试准备 / 技术选型 / 行业研究 / 写作素材？——决定材料的"深度配比"与组织方式
2. **读者底子**：已经知道什么？（把新资料与读者已有知识勾连是最有价值的部分）
3. **时效预算**：想花多少时间？（1 小时速览 vs 一周系统学习，目录结构完全不同）
4. **输出形态**：独立 HTML 页 / Markdown 文档 / 追加进已有知识库？

## 第一步：多源检索（至少三轮，交叉核实）

- **学术源**：arXiv / Semantic Scholar / Google Scholar——找奠基论文、综述、最新修订版。注意 arXiv ID 与 v1/v2 版本时间。
- **一手源**：作者个人博客（hamel.dev、eugeneyan.com 这类）、官方文档、工程博客（Anthropic/Google/Red Hat 等）。一线实践者的博客往往比论文更可操作。
- **社区源**：GitHub awesome 列表、课程课纲（Maven 等）、Hacker News / Reddit 讨论——用于判断"什么真正被实践验证"。
- **书籍源**：O'Reilly / Manning 目录页 + GitHub 配套仓库（读目录定精读范围，不必全书）。

核实纪律：
- 每条资料记录 **作者 / 机构 / 发表时间 / 被引或影响力信号**
- 事实性声明（数据、结论）至少两源交叉；单一来源的标注"待核实"
- 分辨同名不同物（如 EDD 过程模型论文 2411.07781 vs EDDOps 2411.13768）
- 链接必须在写作时验证可达；引用数表述用量级（"被引 400+"）不用精确值

## 第二步：按"目的"分层组织（核心步骤）

不要按"来源类型"组织（一堆"博客区/论文区"没有信息量），要按**读者的学习/使用路径**组织：

| 目的 | 组织方式 |
|---|---|
| 学习入门 | 学习路径表（D1~Dn，每天读什么+自测标准）→ 奠基材料 → 系统化 → 进阶前沿 |
| 面试准备 | 核心概念卡片 → 高频问题 × 回答要点 → 与自己项目经验的勾连表 → 一句话口袋版 |
| 技术选型 | 候选方案对照表（定位/优势/成本/何时选它）→ 决策树 → 落地风险清单 |
| 行业研究 | 玩家地图 → 关键动态时间线 → 趋势判断 → 数据来源可信度分级 |
| 写作素材 | 论点 → 支撑证据（带出处）→ 反方观点 → 金句/数据摘录 |

每条资料的注释必须回答：**"核心内容是什么 · 为什么读它 · 读到什么程度算够"**——禁止"很好的资源""内容丰富"这类空话注释。

## 第三步：勾连与内化（区别于普通资料汇总的关键）

1. **与读者已有知识勾连**：新概念 ↔ 读者做过的项目/读过的材料，做成对照表。例："错误分析先行 ↔ 你案例一的幻觉四类归因就是 open coding"。
2. **提炼一句话口袋版**：整份调研压缩成一段面试/汇报可直接引用的话。
3. **标注矛盾与争议**：材料之间观点冲突处显式列出，不和稀泥。
4. **给出"如果只读三样"**：时间紧张时的最小集合。

## 第四步：输出

### HTML 形态（推荐加入知识库时）
- 复用知识库风格：`assets/style.css`、`.tbl` 表格、`.box why` 提示块、`.callout` 口袋版
- 结构：头部定位说明 → 学习路径/使用路径 → 分层资料表 → 勾连表 → 口袋版
- 所有外链 `target="_blank"`；内链用相对路径
- 落库流程：写成 `tools/xxx_page.py` 的 `build()` → 在 `gen_site_v2.py` 的 `main()` 挂载 → 重建跑 `check_links.py` 必须 0 断链

### Markdown 形态（独立交付时）
- 同样结构；表格优先于列表（资料密度高时表格可读性翻倍）
- 交付时附"本次调研的局限"（哪些方向没覆盖、哪些链接未验证）

## 质量清单（交付前自查）

- [ ] 每条资料有三要素：作者/机构/时间 + 核心内容 + 为什么读
- [ ] 组织方式匹配读者目的（不是按来源类型堆砌）
- [ ] 至少一处与读者已有知识/项目的勾连
- [ ] 有"如果只读三样"或学习路径（可执行性）
- [ ] 事实性声明两源核实，单一来源已标注
- [ ] 所有链接本次会话验证过可达
- [ ] 有一句话口袋版
- [ ] 列出了矛盾观点或调研局限（诚实边界）

## 反模式（禁止）

- ❌ 纯链接列表无注释——那是书签不是调研
- ❌ 所有资料平等罗列——必须有优先级与依赖顺序
- ❌ 只收集不勾连——读者已有认知是整理的锚点
- ❌ 编造论文 ID、作者、被引数——查不到就写"待核实"
- ❌ 忽略时效——AI 领域超过 18 个月的"最新"材料要标注时间让读者自行判断
