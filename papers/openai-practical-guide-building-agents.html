A Practical Guide to Building Agents

机构 / 作者OpenAI
时间 / 形式2025.04 · 工程指南
链接官方 PDF · 介绍页
简历关联AI 应用平台 团队管理

总 · 解决什么问题

企业知道要落地 agent，但不知道从哪开始、风险怎么控、边界在哪。

总 · 主旨思路与设计理念

单智能体优先；编排拓扑三分（Single/Manager/Decentralized）；Guardrails 分层 + 人工升级。

一图看懂 · 核心机制

分 · 核心要点

  • Agent 定义三要素：Model（决策大脑）+ Tools（能力）+ Instructions（行为边界与纪律）。
  • 适用判断：只有在'需要持续判断、规则无法穷举、需要自然语言中转'的场景才用 agent；否则用确定性自动化/工作流。
  • 编排三种拓扑：Single Agent（先做这个）、Manager（控制多个工具型子智能体）、Decentralized（多个平级 agent 互相移交）。
  • 防护栏（Guardrails）要分层：内容安全、事实校验、PII 过滤、工具级权限、人工升级（escalation）。

分 · 关键数据与影响力

  • 指南明确建议'从单智能体 + 好工具开始，跑通再扩展'，与大量企业落地经验一致。
  • 已入选众多企业 AI 转型培训材料，是 2025 年传播最广的 agent 落地文档之一。

总 · 一句话总结

把 agent 落地拆成模型/工具/指令/防护栏四件套的工程题。

与简历项目的关联

  • AI 应用平台：平台 0→1 时选择'单一平台 + 意图路由'而非多智能体，可用该指南的编排拓扑论证合理性。
  • 团队管理：防护栏分层思想对应团队工程规范设计（评审分层、发布分层）。

面试怎么结合

场景①被问'从零搭建 agent 的第一步'｜回答：OpenAI 指南第一条就是把 agent 当'带工具和纪律的模型'，先做单智能体把工具质量和指令写透，我 0→1 建平台时同样坚持先单链路后编排。
场景②被问'如何保证线上安全'｜回答：Guardrails 分层清单——输入侧内容过滤、检索侧权限过滤、输出侧事实校验、兜底人工升级，每层可独立开关。

实战复盘 · ✅ 实战还原（真实 struggle，数字以项目口径为准）

Struggle
灰度期出现两类事故苗头：坐席 A 能查到 B 的佣金口径（越权）；个别答案找不到条款依据（无源输出）。金融场景里任何一条都可能升级成合规事件。
问题拆解
按链路位置分层归因：输入层（敏感/注入）→ 检索层（范围与权限）→ 生成层（幻觉）→ 交互层（谁来兜底）。每层定义“事故复现条件”。
调研与测试
对照 OpenAI 落地指南的 Guardrails 清单逐层设计；每层做开关式验证——关闭该层看事故是否复现，证明该层有效性。
解决步骤
① 输入侧敏感与权限过滤 ② 检索层按用户身份做元数据强过滤 ③ 生成层强制引用原文 + 无依据即拒答 ④ 拒答后转人工/相似问题推荐。
验证思路
越权测试用例集全量通过；无依据答案占比作为回归指标；每次发版跑全量防护栏回归。
达成效果
灰度后零越权事故、零合规投诉；无依据输出占比降至【占位：__%】。
