Why Do Multi-Agent LLM Systems Fail?（MAST 失败分类法）

机构 / 作者UC Berkeley 等（Cemri, Pan 等）
时间 / 形式2025.03 · 论文（NeurIPS 2025）
链接arXiv · GitHub
简历关联AI 应用平台 团队管理

总 · 解决什么问题

多智能体系统经常不如单 agent，失败原因从未被体系化归因。

总 · 主旨思路与设计理念

对 LangGraph/AutoGen/CrewAI 真实 trace 实证标注：14 种失败模式、三大层级（规格/智能体间对齐/任务验证），失败大头在 agent 间对齐与验证缺失。

一图看懂 · 核心机制

分 · 核心要点

  • 方法：对 LangGraph、AutoGen、CrewAI 三大主流框架的真实运行 trace 做标注与根因分析。
  • 三大失败层级：①规格与系统问题（目标/角色定义不清）②智能体间对齐失败（信息传递丢失/ disagree / 重复工作，占比最高）③任务验证失败（无验证步骤、过早停止、结果错误未被发现）。
  • 给出 MAST-Data 标注数据集与自动标注器（LLM 标注器在无标签数据上达到较高人工一致率）。

分 · 关键数据与影响力

  • NeurIPS 2025 接收，被引 750+，是 2025 年多智能体领域引用最高的实证论文之一。

总 · 一句话总结

给'要不要上多智能体'提供风险清单与排障检查单。

与简历项目的关联

  • AI 应用平台：你在 0→1 时选择'意图路由的确定性链路'而非多智能体——MAST 说明约四成失败来自智能体间对齐，这正是你当时规避的风险，可反推架构决策的先见性。
  • 团队管理：三大失败层级与人组织的问题同构（目标不清/信息不同步/验收缺失）——用你带 17 人团队的管理经验类比，极其出彩。

面试怎么结合

场景①'要不要把单 agent 升级成多 agent'｜回答：先引 MAST——失败大头不在单模型能力而在 agent 间对齐与验证缺失；我会先补验证层（评测闭环），再把确有并行收益的环节拆成 subagent，并用 Anthropic 的 15× token 数据算成本账。
场景②'你们怎么排查 agent 链路问题'｜回答：按 MAST 三层级建立检查单——先查任务规格、再查传递信息、最后查验证，一次讲清排障框架。

实战复盘 · ✅ 实战还原（真实 struggle，数字以项目口径为准）

Struggle
老板与客户都在问“要不要把平台升级成多智能体”——行业全部在吹 multi-agent，不跟显得落后。
问题拆解
用 MAST 三层级反问：我们当前的失败大头在哪？分析结论：验证缺失（可补）与单 agent 能力边界（可换模型），而非 agent 间对齐——因为我们根本没有多 agent，先补验证层收益最大。
调研与测试
精读 MAST（被引 750+，NeurIPS 2025）的 14 种失败模式；用 Anthropic 的 15× token / 90.2% 数据算“上多智能体”的成本收益账；对深度研究类需求做并行拓扑原型。
解决步骤
① 短期不上多智能体，资源投给验证层（评测闭环）与检索质量 ② 深度研究类需求用受控并行取数拓扑（非自主多智能体）③ 每季度复盘 badcase 分布。
验证思路
badcase 按三大层级归类统计，观察是否迁移出“确需多智能体”的特征；原型对比并行拓扑的耗时与覆盖率。
达成效果
避免了为 hype 买单的资源浪费；架构决策第一次有了外部实证依据。
