Context Engineering for AI Agents: Lessons from Building Manus

机构 / 作者Manus（蝴蝶效应团队）
时间 / 形式2025.07 · 工程博客
链接原文
简历关联AI 应用平台 性能优化

总 · 解决什么问题

长周期 agent 的上下文爆炸与注意力漂移：成本数量级上升、目标丢失、任务失败。

总 · 主旨思路与设计理念

KV-cache 命中率是最重要产品指标；append-only 上下文；文件系统当外部记忆；todo 复述操纵注意力；保留错误供学习。

一图看懂 · 核心机制

分 · 核心要点

  • KV-cache 命中率是 Manus 最重要的产品指标：影响成本与延迟的数量级；实现手段——prompt 前缀稳定（不写时间戳等易变内容）、上下文只追加不修改（append-only）、必要时人为打乱 JSON 序列化的键顺序以保持缓存命中。
  • 工具定义的演进：不要把工具从上下文中'删除'（会破坏缓存且造成模型困惑），而是用 masking（logit 偏置屏蔽） 控制这一步可用哪些工具。
  • 用文件系统当终极上下文：超长内容放文件、上下文里只留句柄，突破了上下文窗口限制且容量无上限。
  • 通过复述（Todo.md 反复重写）操纵注意力，缓解'目标丢失'；让模型保留过去的错误并从中学习（保持错误在上下文中），避免 few-shot 固化。

分 · 关键数据与影响力

总 · 一句话总结

上下文工程的第一手实战手册，六条实践可直接移植。

与简历项目的关联

  • AI 应用平台：你在多轮对话里做摘要压缩控 token，与 Manus 的'文件系统当上下文'是同一问题的两种解法——成本视角完全一致。
  • 性能优化：KV-cache 命中率优化与你做过的缓存与流量整形思想同源——把系统性能思维迁移到 LLM serving。

面试怎么结合

场景①'多轮对话 token 怎么控'｜回答：两层——模型无关的上下文工程（摘要/句柄化/append-only 保 KV-cache）+ 模型侧压缩；引用 Manus 的 KV-cache 指标观。
场景②'你的平台怎么降本'｜回答：先算单次会话成本账（检索+推理+prompt 各占多少），再按 KV-cache 命中率、上下文长度两条线优化，给出你项目的实际降幅。

实战复盘 · ✅ 实战还原（真实 struggle，数字以项目口径为准）

Struggle
场景模拟培训是多轮长对话：token 成本随轮次线性膨胀，响应越来越慢、账单越来越贵，客户开始质疑 ROI。
问题拆解
把成本拆成输入/输出两侧，输入占大头；上下文里大量是早期对话原文。三个抓手：少带（压缩）、按需带（句柄化）、缓存友好（KV）。
调研与测试
对比“全量保留 / 滑动窗口 / 摘要压缩”三方案在多轮一致性评测上的表现；参考 Manus 的 KV-cache 视角设计稳定前缀。
解决步骤
① 长对话摘要压缩替代原文 ② 关键事实抽取进固定区 ③ 系统提示前缀稳定提升缓存命中 ④ todo 式目标复述防漂移。
验证思路
多轮一致性评测集（答案是否还记得前文约束）+ 单会话 token 成本前后对比。
达成效果
用户满意度提升 35%；单会话输入 token 下降【占位：__%】。
